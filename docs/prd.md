# PRD: 30초 브리프 (30s Brief) MVP

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v0.1 (Draft) |
| 관련 문서 | `docs/proposal.md` |
| 한 줄 정의 | 출근길 30초 안에 국내·세계 핵심 이슈와 "내 지갑·일상 영향"을 확인하는 로그인 없는 웹 대시보드 |

---

## 1. 배경 및 문제 정의

### 1.1 배경
국내외 이슈는 환율·금리·물가·증시를 통해 개인의 지갑에 직접 영향을 주지만, 이를 매일 확인하는 비용은 높습니다.

### 1.2 문제
| # | 문제 | 결과 |
| --- | --- | --- |
| P1 | 포털 뉴스에 연예·가십·낚시성 기사가 섞여 있어 중요한 이슈를 고르는 데 시간이 든다 | 핵심 이슈 누락, 피로감 |
| P2 | 뉴스레터는 메일함을 열어 긴 글을 읽어야 해서 부담스럽고 쌓이기만 한다 | 읽지 않고 방치 |
| P3 | 외신·글로벌 금융 사이트는 정보가 방대하고 영문 위주라 해석이 어렵다 | 해외 이슈 파악 포기 |
| P4 | 이슈가 "내 일과 지갑에 어떤 영향인가"로 번역되어 있지 않다 | 정보를 봐도 행동·판단으로 연결 불가 |
| P5 | 팀 대화·단톡방에서 공유하기 편한 형태가 없다 | 정보 공유 비용 증가 |

### 1.3 해결 방향
**핵심 단어(Tag) + 팩트 한 문장 + 내 지갑·일상 영향 한 줄**의 3단 압축 구조를 국내(KR)와 5개 권역(US, CN, JP, EU, ME)에 일관되게 제공하고, 전 과정을 100% 배치 자동화로 운영해 유지보수 비용을 0에 가깝게 한다.

## 3. 제품 목표 및 성공 지표

### 3.1 제품 목표
- **G1.** 30초 안에 하루 핵심 이슈를 파악할 수 있는 경험 제공
- **G2.** 출근길 루틴으로 자리 잡는 재방문 확보
- **G3.** 사람 개입 없는 안정적 자동 운영($0 인프라) 검증
- **G4.** 검색 유입(SEO) 기반의 성장 가능성 확인

### 3.2 성공 지표 (HEART)

| 항목 | 지표 | 목표 |
| --- | --- | --- |
| Happiness | 재방문 의향 👍 비율 ("내일도 볼 의향?") | 70% 이상 |
| Happiness | 불만 신호율 (아코디언 3초 내 이탈, "요약 부정확" 신고) | 모니터링 후 기준 설정 |
| Engagement | 아코디언 클릭률 (세션 중 1회 이상) | 25% 이상 |
| Engagement | 원클릭 복사율 (세션당) | 10% 이상 |
| Adoption | 신규 일 UV, 유입 채널 비중(직접·커뮤니티·검색) | 4주차 UV 300 이상 |
| Adoption | `/archive` 자연 검색 노출·클릭 주간 증가율 | 우상향 |
| Retention | D7 재방문율 | 20% 이상 |
| Retention | 주 평일 방문 일수 (활성 사용자) | 3일 이상 |
| Task Success | 30초 스캔 완료율 (스크롤 80% 이상 또는 체류 20~60초) | 측정 후 기준 설정 |
| Task Success | 배치 성공률 / 갱신 후 3시간 내 노출 비율 | 95% 이상 |

### 3.3 판정 기준
- **북극성 지표:** D7 재방문율 20% 이상 + 원클릭 복사율 10% 이상
- **판정 시점:** 4주차 종료 시. 2개 이상 달성하면 Phase 2(수익화) 진행, 미달이면 요약 품질과 노출 시간대 가설 재점검
- **측정 도구:** Vercel Analytics 또는 GA4 이벤트 (`copy_brief`, `accordion_open`, `feedback`)
- 목표 수치는 가설이며 1~2주차 실측 후 조정한다.

## 4. MVP 기능 명세

공통 용어: **이슈 카드** = 핵심 단어(Badge) + 팩트 한 문장(40~55자) + 내 지갑·일상 영향(`market_impact`) 한 줄.

### US-1. 메인 대시보드 30초 스캔
**사용자 스토리:** 바쁜 직장인으로서, 접속하자마자 국내·세계 핵심 이슈를 한 화면 흐름으로 훑어보고 싶다, 그래야 출근길 30초 안에 오늘 흐름을 파악할 수 있다.

**기능 요약:** `/` 페이지에 국내 TOP 3 / 세계 TOP 3 키워드, KR·US·CN·JP·EU·ME 6개 권역 카드 그리드(권역당 상위 3개 이슈)를 표시한다.

**인수 조건**
1. **Given** 최신 브리핑이 DB에 존재할 때, **When** 사용자가 `/`에 접속하면, **Then** `[🇰🇷 국내 핵심 TOP 3]`와 `[🌍 세계 핵심 TOP 3]`가 각각 3개 키워드와 한 줄 요약과 함께 첫 화면 상단에 표시된다.
2. **Given** 브리핑 데이터가 있을 때, **When** 메인 그리드가 렌더링되면, **Then** 6개 권역 카드가 표시되고 각 카드는 이슈 3개를 `rank` 순으로 보여주며, 이슈마다 핵심 단어·팩트 한 문장·`market_impact` 한 줄이 모두 노출된다.
3. **Given** 모바일 뷰포트(너비 390px)일 때, **When** 대시보드를 열면, **Then** 레이아웃이 단일 컬럼(국내/세계 상하 배치)으로 전환되고 가로 스크롤이 발생하지 않는다.
4. **Given** 특정 권역의 이슈가 3개 미만일 때, **When** 해당 카드가 렌더링되면, **Then** 없는 자리 대신 "특이 이슈 없음"이 표시되고 페이지 오류가 발생하지 않는다.
5. **Given** 로그인하지 않은 상태일 때, **When** `/`에 접속하면, **Then** 회원가입·로그인·권한 요청 없이 콘텐츠가 즉시 표시된다.

### US-2. 시장 지표 티커
**사용자 스토리:** 개인 투자자로서, 상단에서 주요 시장 지표를 바로 확인하고 싶다, 그래야 간밤 이슈가 시장에 얼마나 반영됐는지 감을 잡을 수 있다.

**기능 요약:** 원/달러 환율, 코스피, 나스닥, 미 국채 10년물 금리, WTI의 현재가와 전일 대비 등락률을 1줄 고정 바(Sticky)로 표시한다.

**인수 조건**
1. **Given** `market_indicators`에 5개 지표가 저장되어 있을 때, **When** 페이지가 로드되면, **Then** 상단 고정 바에 5개 지표의 값과 전일 대비 등락률(▲/▼ 및 색상 구분)이 표시된다.
2. **Given** 사용자가 페이지를 아래로 스크롤할 때, **When** 스크롤 위치가 변경되어도, **Then** 티커 바는 화면 상단에 고정되어 계속 보인다.
3. **Given** 특정 지표의 수집이 실패했을 때, **When** 티커가 렌더링되면, **Then** 해당 지표만 "-"로 표시되고 나머지 지표와 페이지는 정상 동작한다.
4. **Given** 지표 스냅샷이 있을 때, **When** 사용자가 티커를 확인하면, **Then** 지표 기준 시각이 함께 확인 가능하다.

### US-3. 이슈 상세 아코디언
**사용자 스토리:** 투자자로서, 관심 있는 이슈를 눌러 배경과 근거를 사이트 이탈 없이 확인하고 싶다, 그래야 요약을 검증하고 맥락을 이해할 수 있다.

**기능 요약:** 이슈 카드를 클릭하면 카드 하단이 펼쳐져 배경 맥락 3줄, 향후 관전 포인트 1줄, 원문 기사 출처 링크를 표시한다.

**인수 조건**
1. **Given** 이슈 카드가 접힌 상태일 때, **When** 사용자가 카드를 클릭하면, **Then** 외부 페이지로 이동하지 않고 카드 하단이 펼쳐져 배경 맥락 3줄, 관전 포인트 1줄, 출처 언론사명과 링크가 표시된다.
2. **Given** 카드가 펼쳐진 상태일 때, **When** 사용자가 같은 카드를 다시 클릭하면, **Then** 패널이 접힌다.
3. **Given** 출처 링크가 표시될 때, **When** 사용자가 링크를 클릭하면, **Then** 새 탭(`target="_blank"`, `rel="noopener noreferrer"`)으로 원문이 열리고 현재 대시보드는 유지된다.
4. **Given** 사용자가 아코디언을 펼칠 때, **When** 펼침이 발생하면, **Then** `accordion_open` 이벤트가 이슈 ID와 권역 코드와 함께 전송된다.
5. **Given** `context_3lines`가 비어 있는 이슈일 때, **When** 사용자가 펼치면, **Then** 빈 영역 대신 출처 링크만 표시되고 오류가 발생하지 않는다.

### US-4. 원클릭 브리핑 복사
**사용자 스토리:** 직장인으로서, 오늘의 핵심을 한 번에 복사해 팀 슬랙·카카오톡에 공유하고 싶다, 그래야 따로 정리하지 않고 대화를 주도할 수 있다.

**기능 요약:** `[📋 오늘의 30초 브리핑 복사]` 버튼 클릭 시 국내·세계 핵심 키워드 6줄 요약과 서비스 URL을 텍스트로 클립보드에 복사한다.

**인수 조건**
1. **Given** 대시보드가 로드되어 있을 때, **When** 사용자가 복사 버튼을 클릭하면, **Then** 클립보드에 날짜, 국내·세계 핵심 키워드 6줄(키워드 + 한 줄 요약), 서비스 URL이 순서대로 일반 텍스트로 복사된다.
2. **Given** 복사가 성공했을 때, **When** 클릭 직후, **Then** 2초 이내에 "복사되었습니다" 토스트가 표시되고 자동으로 사라진다.
3. **Given** 클립보드 API를 사용할 수 없는 환경(권한 거부 등)일 때, **When** 사용자가 버튼을 클릭하면, **Then** 대체 방식(`execCommand` 또는 선택 가능한 텍스트 모달)으로 복사 가능하게 하고 실패 메시지를 노출하지 않는다.
4. **Given** 복사가 실행될 때, **When** 클릭이 발생하면, **Then** `copy_brief` 이벤트가 전송된다.
5. **Given** 복사된 텍스트를 카카오톡·Slack에 붙여넣을 때, **When** 확인하면, **Then** 줄바꿈과 이모지가 깨지지 않고 표시된다.

### US-5. 일자별 브리핑 아카이브
**사용자 스토리:** 투자자로서, 과거 날짜의 브리핑을 다시 보고 싶다, 그래야 금리·환율 이슈의 흐름을 복기할 수 있다.

**기능 요약:** `/archive/YYYY-MM-DD`에서 해당 일자의 대표 브리핑을 정적 캐싱(ISR)으로 제공한다. 일자 간 이동 UI를 제공한다.

**인수 조건**
1. **Given** `briefing_date`가 2026-01-15인 브리핑이 존재할 때, **When** `/archive/2026-01-15`에 접속하면, **Then** 해당 일자의 대시보드와 동일한 구성(TOP 3, 권역 카드, 티커 스냅샷)이 표시된다.
2. **Given** 브리핑이 없는 날짜일 때, **When** 해당 URL에 접속하면, **Then** HTTP 404와 함께 "해당 일자의 브리핑이 없습니다" 안내, 가장 가까운 날짜로 이동하는 링크가 표시된다.
3. **Given** 아카이브 페이지일 때, **When** 사용자가 이전·다음 날짜 버튼을 클릭하면, **Then** 존재하는 인접 일자의 페이지로 이동한다.
4. **Given** 아카이브 페이지가 응답될 때, **When** HTML을 확인하면, **Then** 일자가 포함된 `<title>`, `meta description`, canonical URL이 설정되어 있고 `sitemap.xml`에 포함된다.
5. **Given** 같은 날 여러 회차 배치가 실행되었을 때, **When** 아카이브를 조회하면, **Then** 해당 일자의 최신 회차 내용이 표시된다(일자당 1건 UPSERT).

### US-6. 키워드·테마별 모아보기
**사용자 스토리:** 투자자로서, 금리·환율·AI·반도체·지정학 같은 키워드별로 과거 이슈를 모아보고 싶다, 그래야 특정 주제의 흐름을 따라갈 수 있다.

**기능 요약:** `/topic/[tag]` 또는 `/search`에서 키워드/권역 기준으로 이슈 히스토리를 필터링해 최신순으로 표시한다.

**인수 조건**
1. **Given** "금리" 키워드를 포함한 이슈가 여러 일자에 존재할 때, **When** `/topic/금리`에 접속하면, **Then** 해당 키워드의 이슈가 최신순으로 일자와 함께 목록 표시된다.
2. **Given** 검색 결과가 20건을 초과할 때, **When** 목록이 표시되면, **Then** 페이지네이션 또는 "더 보기"로 20건씩 로드된다.
3. **Given** 일치하는 이슈가 없는 키워드일 때, **When** 검색하면, **Then** "결과가 없습니다" 안내와 인기 키워드 추천이 표시된다.
4. **Given** 권역 필터(예: US)를 선택했을 때, **When** 결과가 표시되면, **Then** 해당 권역의 이슈만 표시된다.
5. **Given** 검색어에 특수문자·SQL 구문이 입력될 때, **When** 쿼리가 실행되면, **Then** 파라미터 바인딩으로 처리되어 오류나 데이터 노출이 발생하지 않는다.

### US-7. 만족도 피드백 수집
**사용자 스토리:** 서비스 운영자로서, 사용자의 만족 여부와 요약 오류를 간편하게 수집하고 싶다, 그래야 MVP 성공 여부와 AI 품질을 판단할 수 있다.

**기능 요약:** 대시보드 하단에 "내일도 볼 의향?" 👍/👎, 이슈별 "요약 부정확" 신고를 제공한다. 로그인이나 개인정보 입력은 받지 않는다.

**인수 조건**
1. **Given** 대시보드 하단일 때, **When** 사용자가 👍 또는 👎를 클릭하면, **Then** `feedback` 이벤트(값, 브리핑 ID)가 전송되고 "의견 감사합니다" 메시지가 표시된다.
2. **Given** 사용자가 이미 피드백을 제출했을 때, **When** 같은 브리핑에서 다시 접속하면, **Then** 버튼이 비활성화되거나 제출 완료 상태로 표시된다(브라우저 로컬 저장 기준).
3. **Given** 이슈 카드의 신고 버튼을 클릭할 때, **When** 신고가 제출되면, **Then** 이슈 ID와 사유가 저장되고 사용자 식별 정보는 저장되지 않는다.
4. **Given** 짧은 시간에 동일 브라우저에서 반복 제출될 때, **When** 10회를 초과하면, **Then** 추가 제출이 무시되거나 제한 메시지가 표시된다.

### US-8. 자동 수집·요약 파이프라인
**사용자 스토리:** 운영자로서, 사람 개입 없이 최신 이슈가 자동으로 수집·요약·발행되기를 원한다, 그래야 유지보수 비용 없이 서비스를 운영할 수 있다.

**기능 요약:** GitHub Actions가 3시간 주기(일 8회)로 Python 스크립트를 실행해 RSS를 수집하고, Gemini Flash가 Structured Outputs(JSON Schema)로 요약하며, Supabase에 UPSERT 후 Next.js 재검증 웹훅을 호출한다.

**인수 조건**
1. **Given** 배치 스케줄 시각이 되었을 때, **When** 워크플로가 실행되면, **Then** 수집 → 요약 → DB UPSERT → `/api/revalidate` 호출이 순서대로 완료되고 `system_logs`에 `status=success`가 기록된다.
2. **Given** 동일 일자에 배치가 재실행될 때, **When** UPSERT가 수행되면, **Then** `briefings`는 `briefing_date` 기준 1건, `issues`는 중복 없이(권역·순위 기준) 갱신된다.
3. **Given** 일부 RSS 소스가 실패했을 때, **When** 배치가 진행되면, **Then** 성공한 소스로 브리핑을 발행하고 실패 소스는 `system_logs`에 기록되며, 전체 실패 시 직전 브리핑이 유지된다.
4. **Given** 배치가 실패했을 때, **When** 워크플로가 종료되면, **Then** `health_check`/`system_logs`가 갱신되어 Supabase 일시정지를 방지하고 Slack 또는 이메일 알림이 발송된다.
5. **Given** 재검증 웹훅이 호출될 때, **When** 유효한 시크릿 토큰이 없으면, **Then** `/api/revalidate`는 401을 반환하고 캐시를 갱신하지 않는다.
6. **Given** 배치 1회 실행일 때, **When** 소요 시간을 측정하면, **Then** 평균 60초 이내에 완료된다.

### US-9. AI 요약 품질 검증 및 노이즈 필터링
**사용자 스토리:** 사용자로서, 요약이 사실에 근거하고 가십이 없기를 원한다, 그래야 서비스를 신뢰할 수 있다.

**기능 요약:** 프롬프트와 후처리 검증으로 연예·스포츠·단순 범죄를 배제하고, 중복을 병합하며, 입력에 없는 수치를 폐기한다.

**인수 조건**
1. **Given** 입력 헤드라인에 연예·스포츠 결과·단순 범죄 항목이 포함되어 있을 때, **When** 요약이 생성되면, **Then** 결과의 `issues`에 해당 주제가 포함되지 않는다(테스트 픽스처 20건 기준 100% 배제).
2. **Given** 요약 결과에 숫자가 포함될 때, **When** 검증 스크립트가 실행되면, **Then** 입력 헤드라인·스니펫에 없는 수치가 포함된 이슈는 폐기되거나 재생성된다.
3. **Given** 동일 사건을 다룬 여러 매체의 헤드라인이 입력될 때, **When** 요약이 생성되면, **Then** 하나의 이슈로 병합되어 권역당 최대 3개만 출력된다.
4. **Given** 모든 이슈일 때, **When** 결과가 저장되면, **Then** `market_impact`가 비어 있지 않고 1문장이며, 단정·투자 권유 표현(예: "매수하라") 없이 비단정 문체이다.
5. **Given** 모델 출력이 JSON Schema를 위반할 때, **When** 파싱하면, **Then** 최대 2회 재시도 후 실패 시 해당 권역은 발행에서 제외되고 로그에 기록된다.

### US-10. 서비스 소개 및 면책 고지
**사용자 스토리:** 사용자로서, 데이터 출처와 AI 요약임을 알고 싶다, 그래야 정보를 적절한 신뢰 수준으로 활용할 수 있다.

**기능 요약:** `/about`(서비스 소개·출처·면책)과 `/privacy`(개인정보처리방침) 정적 페이지를 제공한다.

**인수 조건**
1. **Given** 모든 페이지일 때, **When** 푸터를 확인하면, **Then** `/about`과 `/privacy` 링크가 노출된다.
2. **Given** `/about` 접속 시, **When** 페이지가 표시되면, **Then** 데이터 출처(Google Trends/News RSS 등), "AI(Gemini) 요약이며 오류가 있을 수 있음", "투자 조언이 아님" 문구가 포함된다.
3. **Given** 대시보드일 때, **When** 화면 하단 또는 정보 아이콘을 확인하면, **Then** "AI 요약, 투자 조언 아님" 요약 고지와 마지막 갱신 시각이 표시된다.
4. **Given** `/privacy` 접속 시, **When** 페이지가 표시되면, **Then** 수집 항목(분석용 익명 이벤트)과 쿠키·분석 도구 사용 여부가 명시된다.
